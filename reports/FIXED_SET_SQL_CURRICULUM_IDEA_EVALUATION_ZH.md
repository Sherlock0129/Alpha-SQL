# 错误感知 SQL 选择器课程学习：选题与可行性评估

评估日期：2026-10-20。使用 idea-evaluator；文献依据为 [配套调研](D:/University/Alpha-SQL/reports/FIXED_SET_SQL_CURRICULUM_RESEARCH_UPDATE_ZH.md)。本报告是研究决策建议，不是论文录用预测，也不是新方法的实验结果。

## 1. 第一印象与选题定位

研究范式为实验型 CS/AI。更准确的论文定位是 New Setting 下的方法与机制研究，而不是一个已确立的 Novel Problem：固定 SQL 候选训练池和模型，检验错误类型是否改善监督式选择器的训练预算分配。

一句话故事：**在不增加候选 SQL、不改变选择器的条件下，验证错误语义相对 loss/margin 的训练调度增量，并检验它是否在计入诊断成本后缩短达标时间。**

“用课程更快训练模型”过宽；“错误感知课程”也不足以构成贡献。可保留的三个主张候选是语义增量、净效率、回归受控，三者均待实验。

## 2. 先审查可能使当前主张不成立的问题

| 问题 | 严重性 | 依据与具体应对 |
|---|---|---|
| F6：现有数据/流程不足以验证广泛训练加速 | MAJOR，可修复但尚未完成 | 只有 38/82 个 pair、默认 batch 128；缺乏共同流程下的 time-to-target。先统一 mini-batch/anchor 规则，测真实成本，限定 pilot 主张 |
| F1：若仅声称“按错误组动态采样”，与近邻差异不清 | MINOR，限于下述收窄版 | 已有技能/错误反馈、排序课程与 SQL 错误建模。需明确条件增量和成本对照；若实施后仍只是套用组 loss，则创新问题不能靠改标题消除 |

没有证据表明“错误感知课程”这一核心机制已被本项目实验否定，因为它还没有被实现并隔离测试。已有 hard-focused reranker 的 75% 对 SC 的 76%，测试的是不同训练样本和选择策略，不能拿来否定未测课程；同样不能写成它已有效。

但若把课题改回“当前 Jev 直接替换 SC 已提高准确率”，本地 287 题的下降会直接反驳该前提。这不是本次评估的研究版本。不能用继续调参承诺掩盖已经失败的历史主张。

### 最接近的五项工作与真正差异轴

| 一手工作 | 已经覆盖 | 收窄版的实际差异；仍需证据 |
|---|---|---|
| Chen、Roberts 等，2023，[Skill-it!](https://arxiv.org/abs/2307.14430) | 技能反馈、影响关系和采样配比 | 对象为固定 SQL pair；检验错误语义超越相同控制器的训练动态输入 |
| Chen、Hu 等，2025，[Aioli](https://arxiv.org/html/2411.05735v2) | 在线组混合与简单分层基线 | 不把组配比本身当创新；测排序任务净达标时间与回归 |
| Choi、Sung 等，2026，[LogFloor](https://arxiv.org/html/2608.14936v1) | 技能门槛、首次达标、路径/静态混合分离 | SQL 错误组信号与含诊断墙钟；不是首次研究 bottleneck/first-passage |
| Cai、Gao 等，2025，[KPO](https://arxiv.org/html/2506.00441) | LLM ranking 的 K-aware 课程 | 不改变 ranking objective，只调度同一正负 pair；不能声称首次给 ranker 做课程 |
| Hong、Chen 等，2026，[ErrorLLM](https://arxiv.org/html/2603.03742v2) | SQL 错误类型、检测与定向修订 | 标签只影响训练调度，不增加扰动 SQL、error-token 模型或推理修订 |

这些差异说明不能直接判定完全重复，但只构成值得测试的设置差异，不保证足够的方法创新。检索未发现直接同题，不等于首创已获确认。

## 3. 生命周期与能力匹配

| 方面 | 已知输入 | 判断 |
|---|---|---|
| 类型 | 已有 SQL pipeline，拟改训练调度 | 应用型方法/实证研究 |
| 竞争周期 | 2025–2026 年已有 ranking、error modeling、mixing 新作 | 建议按约 3–6 个月的应用研究窗口管理；是规划判断，不是到期预测 |
| 数据 | 可访问 BIRD 和既有本地候选/执行缓存 | 可做 pilot；有效 pair 与错误组支持很稀疏 |
| 硬件 | 历史训练记录为 RTX 3070 Ti Laptop GPU | 既有 MLP 已运行；大模型吞吐、显存余量和占用本轮未验证 |
| 每周有效时间/截止日期 | 尚未提供 | 无法作 green 的工期承诺，暂为 Yellow |
| 技能与团队 | 项目已有代码和 GPU 运行记录 | 不据此推断用户个人 PyTorch 深度、团队人力或理论能力 |

当前能合理匹配的是小模型机制 pilot。论文级多设置、多 seed、标签审计与新 held-out 验证需要另做预算。没有必要为迎合“更高效”而先扩成全模型、全数据、大规模 RL 项目。

## 4. 五维评分：以 5 为起点，不把机制当实测

| 维度 | 分数 | 证据与调整理由 | 提升评分所需实验 |
|---|---:|---|---|
| Higher：准确性 | 5/10 | 尚无课程提升 EX 的结果；历史硬例训练未改善总体结果，但不是课程反证。没有足够依据上调 | 相同预算和共同 gate 下提高 EX，分解 fix/regression |
| Faster：训练效率 | 7/10 | 机制判断、未经数据确认：少练冗余样本，向可学习弱组分配预算，已有明确实现路径。小池中诊断可能反而更贵 | 相同目标的稳定达标总时间，计入全部新增成本，多 seed 配对比较 |
| Stronger：稳定性 | 6/10 | 机制判断、未经数据确认：基础分布回放针对历史“修复被回归抵消”这一具体风险；不是已获泛化结果 | SC-correct retention、遗忘及 db-disjoint 验证，不仅报 hard subset |
| Cheaper：数据/总体成本 | 5/10 | 固定训练集不比同样固定集的随机基线更省数据；错误标注还有额外成本，没有上调依据 | 冷启动与复用两种成本核算，证明无需昂贵新增标签 |
| Broader：适用范围 | 5/10 | 目前只设计 SQL selector，没有跨任务验证，无上调依据 | 至少另一真实候选池/共同模型设置；跨任务主张另需实验 |

优先论点应为 Faster，辅以 Stronger。Higher 是约束和潜在附带收益，不应先承诺更高终点 EX。三个维度仍在 5 分说明故事还未充分展开；评分不预测某个百分比或加速倍数。

## 5. 范式变化探查

| 问题 | 回答 | 理由 |
|---|---|---|
| 是否挑战未被讨论的基本假设 | No | 训练顺序/预算分配早已被研究，不能把“随机非最优”包装成新发现 |
| 是否解决公认但一直回避的大问题 | Partial | 成本与质量归因重要，但已有 Aioli、LogFloor 等正面研究 |
| 是否依赖新技术周期才可行 | No | 当前实现可由已有标签、AST 和普通训练动态完成 |
| 成功后是否改变领域核心优先级 | No，尚无依据 | SQL selector 局部节省可能有价值，但尚无改变整个领域的证据 |

定位为增量研究；目前没有充分的范式转移依据。不应通过“颠覆现有 NL2SQL 训练范式”的措辞提高故事强度。

## 6. 可行性、决定性实验与停止条件

| 风险 | 等级 | 应对 |
|---|---|---|
| 计算 | MLP pilot 低；较大模型未知 | 先测基础训练、数据处理及 probe 的时间占比；不启动未授权的大模型训练 |
| 数据 | 高 | 固定当前池做流程验证；报告每组独立题数，稀疏组先合并，不重复 pair 冒充新问题 |
| 工程 | 中 | 共用 sampler 接口、独立随机数、曝光日志和 pointwise 预算，避免修改流程造成伪收益 |
| 测量/归因 | 高 | 标签打乱、loss/progress、one-shot、静态组平衡及同曝光乱序控制 |
| 工期 | 未知 | 交付时间和每周投入未提供；先列依赖与完成门槛，不承诺固定日期 |

### 决定性验证

冻结同一模型、候选/标签/pair、初始化、优化器、batch 和预算。第一轮先比较 Uniform、Loss/progress-only、Static error-balanced、One-shot weighting、Dynamic error-aware；若使用阶段开放，立即加入 Random pacing。正式方法结论还需同预算技能/瓶颈控制基线。

仅让 scheduler 使用语义错误元信息，不向 reranker 额外输入纠错解释。用固定训练诊断面板估计错误/进度，validation 决定超参及达标目标，未反复分析的 test 只作外部终局检验。若另用 monitor split，则承认其适应性监督用途。所有组的监督访问和评估预算一致。

预先规定可接受的质量差距及达标规则，并以验证目标稳定首次达标总时间为主指标；阈值不能看 test 后设定。另报固定时间预算的 EX、条件选择准确率、回归率、未达标 seed 和每类支持数。现有 100/287 题可继续 debug，但不能重新称为新方法完全未见的 test。

### 应改变结论的结果

- 语义标签打乱与真实标签一样好：不支持语义增量，改为配比/训练动态研究。
- 一次性重加权同样好且更便宜：放弃“持续动态诊断必需”的主张。
- 只减少 steps、不减少总时间：只称样本/更新效率，不称真实训练加速。
- hard 修复被普通题回归抵消：不声称总体选择质量改善。
- 统一 mini-batch 后所有方法已很快收敛：当前模型没有足够真实加速空间，不人为放大网络或延时制造结果。

这些是未来实验的证伪条件，不是保证通过的乐观阈值。若隔离实验已经让核心机制输给强控制，应停止该版本主张，而不是继续堆模块。

## 7. 判定与前三项行动

**Accept with Revisions：收窄后值得做验证，不建议立即以“新型错误感知课程方法”定稿。**

理由：问题可实验化、与历史回归有具体联系，且能复用现有缓存；但新颖性集中在尚未测得的语义增量，训练效率的测量基础尚不成立。当前证据不足以给 Strong Accept，也不足以否定未测试的核心机制。

先完成三项：

1. 统一真实 mini-batch、pointwise anchor 和计时流程，测清单步训练与诊断成本；修正是共同基础设施，不计入课程贡献。
2. 冻结错误标签、支持数和最小五组协议；以多个配对 seed 检验语义增量、净时间与回归，不新增候选、不读取 test 调度。
3. 依据决定性对照决定扩大、简化或停止：只有存在净收益且超越强采样基线，才在更有代表性的共同固定池/模型上复验并拟论文主张。

本轮只新增调研和评估文档；没有修改训练实现、重跑旧测试或宣布任何新性能。deep-research 引入的反证与近邻核验使选题从泛称课程收窄为条件增量与净成本；idea-evaluator 进一步将数据/流程可识别性列为推进前置条件。
